How does FSD convert the raw pixel values of 8 cameras into one 3D description of the road?

Written 2026-09-29 · Main path: about 28 minutes · Complete page: about 35 minutes · You need to know: what a matrix is, and that a neural network is a function that learns from examples

The short answer

Each of the 8 cameras delivers 1,280 × 960 raw sensor values, 36 times per second. Together this is about 354 million values per second. The network reduces these values in 4 stages.

Stage 1, convolution: a small matrix (a kernel) slides over the image and calculates one number for each position. Many such matrices in many layers turn pixels into features. A feature is a number that describes a small region: an edge, a wheel, a lane mark.

Stage 2, several scales: the features exist at 4 resolutions, from 320 × 240 positions down to 40 × 30. A second network (BiFPN) mixes the resolutions.

Stage 3, attention: a grid on the road, seen from above, asks all 8 images which features belong to each cell. The answer is a weighted sum of image features. This step converts 8 flat images into one 3D space.

Stage 4, memory and output: the space is aligned with the earlier frames, and output networks read it as occupied cubes (voxels), lanes, and objects. The occupancy network runs in about 10 ms.

1. One example: a 3 × 3 kernel finds an edge in a 6 × 6 image

The first operation of the network is the convolution. A convolution slides a small matrix over the image. At each position, it multiplies each pixel under the matrix with the matrix value at the same place, and it adds the 9 products. The small matrix is the kernel. Training sets the values of the kernel.

The example uses a kernel that finds a vertical edge. Its values are the values of the Sobel operator, a classical edge kernel. So you can check the result by hand.

The image has 6 × 6 pixels. The left half has the value 10, the right half has the value 90. So there is one vertical edge between column 3 and column 4.

Worked example: the kernel at the first 4 positions of row 1
  1. Position 1 (columns 1 to 3): all 9 pixels are 10. Products: −10, 0, 10, −20, 0, 20, −10, 0, 10. Sum = 0. The left column of the kernel is negative and the right column is positive. When both sides have the same brightness, the products cancel.
  2. Position 2 (columns 2 to 4): the right column of the window is 90. Products: −10, 0, 90, −20, 0, 180, −10, 0, 90. Sum = 320. The right side is brighter than the left side by 80. The kernel weights of the two sides are 1, 2, 1, so the sum is 80 × 4 = 320.
  3. Position 3 (columns 3 to 5): the left column is 10, the right column is 90. Sum = 320. The middle column is multiplied by 0, so the middle value does not matter.
  4. Position 4 (columns 4 to 6): all 9 pixels are 90. Sum = 0. Same as position 1: equal brightness on both sides gives 0.

Result: the output row is 0, 320, 320, 0. The output is large exactly where the edge is. The other 3 rows give the same values, because every row of the image is the same. So the output is a 4 × 4 map of "how strong is a vertical edge here".

Three facts about this example transfer to the real network.

  • The output is smaller than the input. A 3 × 3 kernel on a 6 × 6 image gives 4 × 4 outputs. Real networks also skip positions. A stride of 2 means that the kernel moves 2 pixels per step. Then the output has half the width and half the height.
  • One kernel gives one map. A layer has many kernels, for example 64, and gives 64 maps. Each map is a feature map: a grid in which each number describes the region around one position. Each number is a feature. The edge strength of the example is one feature.
  • Layers stack. The next layer applies its kernels to the feature maps, not to pixels. So the second layer sees edges, and a deep layer sees a wheel or a lane mark. Training sets all kernel values.

2. Capture: 8 cameras give 354 million raw values per second, and no image signal processor touches them

Tesla stated the input format at AI Day 2021. Each of the 8 cameras delivers images of 1,280 × 960 pixels with 12 bits per pixel, 36 times per second. In 2022 Tesla added that the network receives the raw sensor values, which Tesla names "photon counts".

Worked example: the size of the raw input
  1. Pixels per image: 1,280 × 960 = 1,228,800.
  2. Bytes per image: 1,228,800 × 12 bits ÷ 8 = 1,843,200 bytes, about 1.8 MB. A 12-bit value needs 1.5 bytes. Real memory stores it in 2 bytes, so the real size is larger.
  3. Values per second, 8 cameras: 1,228,800 × 36 × 8 = 353,894,400, about 354 million.
  4. Levels per pixel: 212 = 4,096. A normal 8-bit image has 28 = 256 levels. The ratio is 16. Tesla states the same ratio: 4 bits more give 16 times the dynamic range.

A normal camera sends its sensor values through an image signal processor (ISP). The image signal processor is a circuit that converts sensor values into a picture for a human eye. It corrects colours, reduces noise, applies a tone curve, and compresses the 12 bits to 8 bits. Tesla removed this circuit from the path to the network in 2022. Tesla stated two reasons. The network receives 16 times more levels, and the time of the image signal processor is saved.

Rectification. Each camera is mounted with a small error of angle and position, and each lens distorts the image in its own way. Rectification is a fixed transformation that converts each image to the image of one standard virtual camera. So the network sees the same geometry in every car.

The example camera of section 3 shows the size of the effect. A tilt of 1 degree moves every pixel by about 15.7 pixels. A tilt of 0.1 degree moves it by 1.6 pixels.

3. Geometry: a point at 10 m lands at pixel (820, 435), and at 40 m at (685, 468.75)

A camera image is a flat projection of 3D space. The pinhole camera model is the formula of this projection. It uses one number, the focal length f, in pixels: the distance from the lens to the image plane, measured in pixel widths. With the centre of the image at (cx, cy), a point at (X, Y, Z) in front of the camera lands at the pixel:

u = f × X ÷ Z + c_x
v = f × Y ÷ Z + c_y

X is the distance to the right of the camera axis, Y is the distance below the axis, and Z is the distance ahead. The example uses f = 900 pixels and the image centre (640, 480). Tesla did not publish the focal length of its cameras. The value 900 is an example value.

Worked example: one point at 4 distances
  1. Point at X = 2 m, Y = −0.5 m, Z = 10 m: u = 900 × 2 ÷ 10 + 640 = 820. v = 900 × (−0.5) ÷ 10 + 480 = 435. Y is negative, so the point is above the axis, and v is smaller than the centre value 480.
  2. Same point at Z = 20 m: u = 900 × 2 ÷ 20 + 640 = 730. v = 457.5. Doubling the distance halves the offset from the centre: 180 became 90.
  3. Same point at Z = 40 m: u = 685. v = 468.75.
  4. Same point at Z = 5 m: u = 1,000. v = 390. At 2.5 m the point would be at u = 1,360, outside the image of 1,280 pixels.

Result: a far point lies near the centre of the image. A near point lies far from the centre. The formula divides by Z, so the image gives no direct value of Z. Two points at (2, −0.5, 10) and (4, −1, 20) land on the same pixel.

The network needs the reverse direction: from a position on the road to the image features that describe it. The formula gives the reverse only in part. A cell of the road grid has a known X and Z, but its content can have any height Y. So the cell corresponds to a vertical line segment in the image, not to one pixel.

Take the cell at X = 2 m and Z = 10 m. All heights from 2 m above the camera to 0.5 m below it lie on the column u = 820, between v = 300 and v = 525. The next section shows how the network selects along this line.

4. Attention: each cell of the road grid takes a weighted sum of image features

The output space of the network is the BEV, the short form of bird's-eye view. The BEV is a grid on the road, seen from above, with the car at a fixed position. Tesla also names it "vector space". An example grid with cells of 0.5 m and a side of 100 m has 200 × 200 = 40,000 cells. Tesla did not publish the size of its grid.

Attention is the operation that fills each cell. Attention works with three kinds of vectors. A query is a vector that says what one output position needs. A key is a vector that says what one input position offers. A value is the content of that input position. The operation compares the query with every key, converts the comparison scores into weights, and returns the weighted sum of the values.

The formula from the paper "Attention Is All You Need" (2017) is:

Attention(Q, K, V) = softmax(Q × Kᵀ ÷ √d) × V

Q, K, and V are the matrices of all queries, keys, and values. d is the length of one query vector. The softmax function converts a list of scores into positive weights with the sum 1. Each weight is escore divided by the sum of all escore. The division by √d keeps the scores small, so that the softmax does not put all weight on one key.

Worked example: one query, 3 keys, d = 16
  1. Scores, query × key: 8, 2, −4. The score is the dot product of the query vector and the key vector. A large score means that the key matches the query.
  2. Scaled scores: 8 ÷ 4 = 2, 2 ÷ 4 = 0.5, −4 ÷ 4 = −1. √16 = 4.
  3. e2 = 7.389, e0.5 = 1.649, e−1 = 0.368. Sum = 9.406.
  4. Weights: 7.389 ÷ 9.406 = 0.786, 1.649 ÷ 9.406 = 0.175, 0.368 ÷ 9.406 = 0.039. The sum of the weights is 1.000.
  5. Output: 0.786 × value 1 + 0.175 × value 2 + 0.039 × value 3. With the example values 0.9, 0.4, and 0.1, the output is 0.781. The output is mostly the value of the best matching key.

Tesla described the use at AI Day 2021 in three steps.

  1. Queries from the grid. Each BEV cell receives a positional encoding: a vector of sine and cosine values of its X and Z. A small network (an MLP, a multilayer perceptron) converts the encoding into the query.
  2. Keys and values from the images. Each position of each feature map of each camera receives its own positional encoding. Two small networks convert the feature and the encoding into a key and a value.
  3. Multiplicative attention. Each query is compared with all keys of all 8 cameras. The cell receives the weighted sum of the values.

Tesla did not state that the network applies the projection formula of section 3. The network learns the correspondence during training. The query of the cell at (2 m, 10 m) learns to give high scores to the keys near column 820. The formula explains why the correct keys lie on one column. The positional encodings make the match possible, because a key without a position could not be matched to a place.

Tesla gave one reason for this design at AI Day 2021. Before, each camera detected objects alone, and program code joined the detections. A large truck near the car appears in up to 5 of the 8 cameras, so the joined result was poor. With attention, the fusion happens on features, before any detection.

The 3D queries of 2022. At AI Day 2022 Tesla described the same operation for the occupancy network. The occupancy network is the output network that gives, for each small cube of space, the probability that an object fills it. Its queries are 3D positions (X, Y, Z) instead of 2D cells. Tesla stated: "We construct a set of 3D position queries along with the image space features as keys and values fit into an attention module".

5. Wrong idea corrected: the cameras are not fused after detection, but before

Common wrong idea

Wrong: "Each camera detects the cars and lanes in its own image. Then a program combines the 8 lists of detections into one map."

Correct: the 8 images are combined at the feature level, before any detection. The attention step of section 5 reads features from all cameras at the same time. The detection happens once, in the BEV.

Why the wrong idea fails: it describes the design of Tesla before 2021. An object that spans several cameras gives several partial detections, and no rule joins them well. Also, a detection in one image has no distance. The fusion of features with positional encodings lets the network learn the distance from all cameras together.

6. Limits: the current network is not public, and the example numbers are not Tesla's

Limits
  • The current network is end-to-end. Since version 12 (2024), one network converts the video into driving commands, and Tesla did not publish its inside. The stages of this page are the last design that Tesla explained.
  • Many numbers are examples. The kernel, the focal length, the grid sizes, the strides, and the attention weights show the mechanism. Tesla published the camera format, the 12 bits, the 27 ms, the 1 m, and the 10 ms.
  • The sources are recordings. The facts of 2021 and 2022 come from an automatic transcript and from a written summary of the videos. I did not watch the videos.
  • The page covers perception only. The planner and the controller are not on this page.

7. Check your understanding

Try to answer before you open each answer.
  1. Apply the kernel of section 1 to a 6 × 6 image in which the left half is 90 and the right half is 10. What is the output row?
    Show the answer

    0, −320, −320, 0.

    The image is mirrored, so the difference between the right side and the left side is −80 instead of 80. The sum is −80 × 4 = −320. The typical wrong answer is 0, 320, 320, 0: the kernel measures the direction of the edge, not only its presence.

  2. Use f = 900 and the centre (640, 480). On which pixel does a point at X = −3 m, Y = 0, Z = 15 m land?
    Show the answer

    (460, 480).

    u = 900 × (−3) ÷ 15 + 640 = −180 + 640 = 460. v = 900 × 0 ÷ 15 + 480 = 480. The point is on the axis in height, so v is the centre value. The typical wrong answer forgets the sign: u = 820.

  3. Why does a BEV cell correspond to a vertical line in the image, and not to one pixel?
    Show the answer

    Because the cell fixes X and Z, but not Y.

    The pixel column u depends on X and Z only. The row v depends on Y and Z. The content of the cell can have any height, so v can take any value along the column. The typical wrong answer is "because of lens distortion". Distortion is removed by rectification before this step.

8. More detail: the backbone gives 76,800 to 1,200 positions per stride, and BiFPN mixes them

The backbone is the first part of the network. It applies many convolution layers to the rectified image and produces feature maps. Tesla uses one backbone per camera, of the type RegNet. RegNet is a family of networks from the paper "Designing Network Design Spaces" (2020). The family is defined by a few numbers. The width and the depth of each stage follow a simple rule. So Tesla can choose a size that fits the computer of the car.

A RegNet has 4 stages. Each stage halves the width and the height of the feature map, and increases the number of maps. The result is a feature pyramid: the same image described at several scales. The next table gives the sizes for the input of 1,280 × 960 pixels. The strides 4, 8, 16, and 32 are the standard strides of this network family. Tesla did not publish its exact values.

How to read this table: each row is one stage of the backbone. "Stride" is the number of input pixels between two neighbouring positions of the feature map. "Positions" is width × height. The last column is a typical meaning of the features at this stage. It is not a statement of Tesla.

The stages have opposite strengths. Stage 1 knows where a lane mark is, to 4 pixels, but a feature there sees only a small region. Stage 4 knows that a car is present, but only to 32 pixels.

BiFPN is a network that mixes the stages. BiFPN is the short form of "bidirectional feature pyramid network", from the paper "EfficientDet" (2020). It passes information from the large scale to the small scale and back, several times, with learned weights for each connection. After BiFPN, a feature at stage 1 also knows that it is part of a car.

In 2021 the output of BiFPN went to several small networks, one per task: traffic lights, lane marks, objects. Tesla named this structure HydraNet. But each camera was still processed alone. Sections 3 and 4 show how the 8 outputs become one space.

9. More detail: the space is aligned over time, and voxels are read out in 10 ms

One frame is not enough. A car hidden behind a truck for one second is still there. A lane mark seen 10 m ago still counts. So the network keeps earlier features.

  • 2021: two queues. Tesla stored BEV features in two queues. The time queue received one entry every 27 ms. The space queue received one entry every 1 m of travel. A network then read both queues. The time queue helps when the car moves fast. The space queue helps when the car waits at a red light for a long time.
  • 2022: alignment with odometry. Odometry is the measured motion of the car: distance, heading, and speed from the wheels and the inertial sensors. Tesla stated that the 3D features are "aligned temporally using vehicle odometry". So the feature grid of 27 ms ago is shifted by the distance that the car moved. Then it is added to the new grid with learned weights.

After the alignment, deconvolution layers increase the resolution of the 3D grid again. A deconvolution is the reverse of a stride: it makes the grid larger. Then the output networks read the grid.

The main output of 2022 is the occupancy network of section 4. It divides the space around the car into voxels, which are small cubes. For each voxel it gives the probability that an object fills it, and the motion of the voxel, which Tesla names occupancy flow. A second output reads the grid at any (X, Y, Z) with a small network and gives finer geometry and the class of the object. Tesla stated that the occupancy network "runs about every 10 milliseconds" on the accelerator of the car.

10. Recap, glossary, and sources

Recap
  1. The input is raw: 8 cameras, 1,280 × 960 pixels, 12 bits, 36 images per second, without an image signal processor.
  2. Convolution kernels turn pixels into features. A RegNet backbone gives feature maps at 4 strides, and BiFPN mixes the scales.
  3. The pinhole formula links a road position to an image column, but not to a row.
  4. Attention fills each cell of the BEV grid with a weighted sum of image features from all 8 cameras. The weights are learned.
  5. The grid is aligned with earlier frames by odometry, and the occupancy network reads it as voxels in about 10 ms.

Glossary

Attention
An operation that compares a query with all keys. It converts the scores into weights with the softmax function and returns the weighted sum of the values.
Backbone
The first part of the network, which applies convolution layers to an image and produces feature maps.
BiFPN, bidirectional feature pyramid network
A network that mixes feature maps of different scales, in both directions, with learned weights.
BEV, bird's-eye view
A grid on the road, seen from above, with the car at a fixed position.
Convolution
The operation that slides a kernel over an image and writes the sum of the products at each position.
Feature
A number that the network calculates from a region of the image, and that describes a property of the region.
Feature map
A grid of features, one per position, produced by one kernel.
Focal length
The distance from the lens to the image plane, measured in pixel widths. The symbol is f.
Kernel
The small matrix of a convolution. Training sets its values.
Occupancy network
The output network that gives, for each voxel, the probability that an object fills it, and the motion of the voxel.
Odometry
The measured motion of the car: distance, heading, and speed.
Pinhole camera model
The formula that maps a 3D point to a pixel: u = f × X ÷ Z + cx, v = f × Y ÷ Z + cy.
Rectification
A fixed transformation that converts each camera image to the image of one standard virtual camera.
Stride
The number of input pixels between two neighbouring positions of a feature map.
Voxel
A small cube of space. It is the 3D form of a pixel.
