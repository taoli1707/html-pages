REPRODUCE_PLAN.md · 237 lines
# Brief: rebuild 清明上河图 (Along the River During the Qingming Festival) as a verified 3D scene

You are an AI agent with a shell, file tools, image reading (vision) and, ideally, the ability to run parallel sub-agents.
This brief describes a project that has already been done once. Your job is to reproduce it with your own setup, so the
result can be compared. Follow the phases in order. Each phase has a deliverable and a check. Do not skip the checks.

---------------------------------------------------------------------------------------------------------------------------

## 0. Goal and success criteria

Goal: a walkable, browser-based 3D reconstruction of the Palace Museum version of 清明上河图 in which every object the scroll shows
(about 814 people, 28 boats, 60 animals, 30+ buildings, 20 vehicles, 8 sedan chairs, 170 trees, plus signs, stalls and props)
stands at its true scroll position, seen from the painting's own viewpoint, with the right form, pose and activity.

The approach is data first: build an inventory and a ground plan from the painting, then generate the 3D scene from that data,
then verify it against the painting tile by tile and correct it in rounds.

Measured result of the reference run (use these as the bar to beat):

| 1 (first full build) | 2.2 | 393 | 572 | 314 |
| 3 (first per-object corrections) | 2.8 | 611 | 542 | 128 |
| 7 | 2.93 | 771 | 445 | 65 |
| 8 | 3.0 (all 41 tiles at 3) | 871 | 369 | 44 |

Report your own numbers in the same table form after every verification round.

## 1. Setup (adapt to your environment)

Reference tools (versions used; newer is fine):
- Blender 5.x run HEADLESS only: `blender -b --python script.py -- args`. Never drive a user's open Blender session.
- Python 3.9+ with Pillow and NumPy in a project venv. Run your own scripts with `python -I` (isolated mode).
- Three.js 0.170 for the web viewer, loading one GLB file.
- A static web host for review pages (the reference used GitHub Pages).

Source image: the Wikimedia Commons scan
`https://upload.wikimedia.org/wikipedia/commons/8/86/Alongtheriver_QingMing.jpg` (38,414 x 1,800 px, about 70 px per cm of silk).
Save it as `research/scan/qm.jpg`.

Project layout to create:
```
research/        data, guides, merge and review scripts
  scan/qm.jpg
  tiles/         tile images
  annot/         per-tile inventory JSON (phase 1)
  plan/tiles/    per-tile ground-plan JSON (phase 2)
  assets/tiles/  per-tile asset specs (phase 3); assets/overrides/ per-tile corrections (phase 5)
  verify/        renders, contexts, verdicts per round (phase 5)
blender/         generators and the scene builder
web/             viewer (index.html + scene .glb)
PLAN.md          living status log: what was done, numbers, known issues, next step
```

Working rules that mattered in the reference run:
1. One vision agent per tile, each with a written GUIDE file and a per-tile context JSON. Never rely on a long prompt alone.
2. Every agent writes one JSON file into a fixed path and replies with a 5-line summary. A stitch script merges the files.
3. Every agent must self-check by drawing its output on the tile image and looking at it before finishing.
4. Keep a hard cap on concurrent agents (the reference used 20) and queue the rest.
5. Archive every round's verdicts (`verify/round1`, `round2`, ...) before the next round overwrites them.
6. Record each round in PLAN.md: numbers, what changed, known systematic issues, next step.
7. Python 3.9 tokenizer bug: very long source lines containing Chinese text raise a false "Non-UTF-8 code" SyntaxError.
   Keep such lines under about 380 bytes.

## Phase 0. Tiles (deliverable: 41 tiles)

- Cut the scan into tiles 1,100 px wide with 200 px overlap (stride 900 px). That gives 41 tiles; the last is 804 px wide.
- Name tiles tile01..tile41. Store each tile's x0 in global pixels and its cm range in `research/tiles/tiles.json`.
- Draw a cm ruler on each tile copy used by agents, so every annotation can carry an absolute scroll position.
- Global x of a tile pixel = tile x + x0. Neighbouring tiles share 200 px: tile N+1 x = tile N x - 900.

Check: tiles stitched back side by side reproduce the scan; overlaps match pixel for pixel.

## Phase 1. Inventory (deliverable: research/catalogue.json + review page)

- Write `ANNOTATION_GUIDE.md`. For every person, animal, boat, vehicle, sedan, building, tree, stall, sign, structure and prop:
  id, type, subtype, bbox in tile px, base point (where it touches the ground, deck or floor), band (near bank, water, far bank,
  road, interior, upper floor, bridge deck), facing, pose (stand, walk, carry-pole, push, pull, squat, sit, kneel, ride,
  lean-on-rail, point, bow, lie, scull, pole...), dress, props, activity, group, readable sign text, confidence.
- Run one vision agent per tile. Merge with a script: recompute cm from pixel geometry, dedupe objects in the 200 px overlap
  bands, union boats and buildings split across tiles, union sign fragments, drop collector seals.
- Assign stable gids by type: P0001 people, A animals, B boats, V vehicles, S sedans, H buildings, T trees, K stalls, G signs,
  X structures, O props, F furniture.
- Keep a `catalogue_fixes.json` for cross-tile duplicates and misreadings (mark them exclude_3d, never delete silently).
- Build a review page: each tile with boxes and per-object crops.

Reference counts: 2,364 objects, 847 people. Expect over-counting of boats (fragments, occluded hulls) and duplicate signs.

## Phase 2. Ground plan and depth model (deliverable: research/plan.json, depth model, overlay page)

- One agent per tile traces polylines in tile px: water polygons, bank lines, roads, building footprints (front line at the
  base), walls, fences, railings, bridges (footbridge, 虹桥 Rainbow Bridge, moat trestle bridge), terrain (hills, fields, mounds).
- Stitch: each tile owns the x-range between the mid-lines of its overlaps; chain polylines across seams.
- Depth model: the painting is an oblique bird's-eye view. Calibrate per scroll position:
  - painter's scale k(cm) in px per metre (about 95 px per adult figure at the bridge, 140 in the city);
  - camera elevation theta about 28.4 degrees, so cot(theta) is about 1.85;
  - a function W(global_x, image_y) -> world (X, Y) in metres, and its inverse.
  Reference: the scroll is about 512 m of ground long and 46-70 m deep.
- Rule for raised objects: anything above the ground (upper floors, decks, roofs, lanterns) is drawn higher on the silk by
  z * cot(theta) * scale. When you convert a raised object's painted pixel to the ground, shift it SOUTH (towards the viewer)
  by z * cot(theta). Forgetting this puts every raised object several metres too far north.

Check: draw the plan on every tile and look at it. Fix seam disagreements by sending both tile agents the evidence.

## Phase 3. Asset specs and generators (deliverable: specs.json, generators, contact sheet)

- One agent per tile writes a spec for every object it owns, following `ASSET_GUIDE.md`:
  buildings (bays, storeys, roof type gable / hip / xieshan 歇山 / pyramid / lean-to / dome, cover tile / thatch / plank / mat,
  eave height, ridge direction, front type open / doors / lattice, awnings, balconies, 彩楼欢门 gate scaffolds, signs, interior);
  boats (length, beam, heading, cabin type, mast up / lowered / none, rudder, sweep, poles, cargo, crew slots);
  vehicles and sedans; trees (trunk and limb polylines, crown box, species form willow / bare / pine / shrub / reed);
  stalls, structures, props.
- Convert pixels to metres through the depth model. Merge per gid, preferring the tile that sees most of the object.
- Write procedural Blender generators, one module per family: buildings, boats, vehicles, trees, people (pose + dress + props),
  props. Each takes a spec and returns one mesh object with vertex colours (one draw call per object).
- Build every asset alone and render it at the 28 degree view; make a contact sheet: scan crop beside render.

Check: every spec builds without error. The reference had 777 of 777 building.

## Phase 4. Assembly and viewer (deliverable: layout.json, scene GLB, viewer page)

- `make_layout.py`: catalogue + plan + depth + specs + per-tile overrides -> `layout.json` with one placement per object
  (location in metres, rotation, scale, height), terrain grid, walls, bridges. Buildings at their traced front line, boats
  from bow and stern, figures on decks, boats, roofs and upper floors lifted to those heights.
- `build_scene.py` (headless Blender): build everything, join static geometry into chunks, animate walkers, polers and
  animals, export one GLB (reference: about 9 MB, about 1 M vertices).
- Web viewer: Three.js, orbit controls, a "compare with painting" mode (scan tile beside the 3D view) and a "painting
  viewpoint" camera.

Check: the viewer loads on desktop and phone at a usable frame rate.

## Phase 5. Verification and correction loop (the core of the project)

### 5a. Matched renders
- One orthographic camera per tile at theta = 28.4 degrees, framing exactly that tile's ground.
- Render all 41 tiles from the built .blend file (Workbench engine, no specular highlights).
- Warp each render row by row AND column by column through the depth model so every object's BASE lands on its painted
  pixel. Use the local scale per column. The reference first used the tile-centre scale and got up to 300 px errors at
  tile edges, which made every agent's measured moves wrong.
- Write two images per tile: `tileNN_pair.jpg` (scan left, render right, 10 px gap) and `tileNN_lab.jpg` (same, with each
  gid drawn at its base point on both halves; green built, grey excluded, red not built).
- Write `ctx/tileNN.json`: the entries this tile owns with gid, type, bbox, base, pose and build status.

### 5b. Verifier agents (one per tile)
`VERIFY_GUIDE.md` tells each agent to:
- judge every non-person entry: ok / wrong (say exactly what: offset in tile px and direction, size, form, collision) /
  missing / ignore (with reason);
- judge people as crowds per area: rough counts painting vs 3D, plus clear errors by gid (floating, in water, inside a roof,
  wrong gender, missing load);
- list extras: things in the 3D that the painting does not have, with tile px;
- give a score 1-5 and a list of systematic problems;
- from round 2 on, read the previous round's verdicts and add "vs_previous": what improved, what got worse, what is still wrong;
- zoom by cropping the SAME window from both halves (right half offset by tile width + 10 px), 6-8 windows per tile.

### 5c. Corrector agents (one per tile)
`FIX_GUIDE.md` tells each agent to turn its tile's verdicts into ONE overrides file `assets/overrides/tileNN.json`:
```
{"tile": "tileNN",
 "objects":   {"<gid>": {"move_px": [dx, dy], "rotate_deg": 0, "scale": 1.0, "z_m": 0,
                         "spec": {partial spec, deep-merged}, "remove": false}},
 "people":    {...same keys, plus pose / dress / facing...},
 "furniture": {...},
 "add":       [{"type": "prop", "anchor": [x, y], "on": "ground", "z_m": 0, "spec": {"kind": "...", ...}}],
 "notes":     "what could not be expressed and why"}
```
- Moves are in painting px (image right +, image down +). Make moves ADDITIVE across rounds (a separate key per round
  convention, e.g. move2_px) so later rounds do not silently replace earlier corrections.
- Anchor rule for added objects that float (lanterns, signs, banners): the anchor is the painted pixel of the object itself,
  plus its z_m; the builder settles it south by z * cot(theta). Anchoring at street level put lanterns 14 m south in a crowd.
- A corrector owns only its tile's gids. If the blocker belongs to a neighbour tile, it reports it; the coordinator relays it
  to that tile's corrector, or applies it after that corrector has finished.
- Correctors undo the previous round's regressions FIRST, then fix the rest.
- Make plan walls and plan bridges overridable by gid (remove, height, width, z) so correctors can fix them without code.

### 5d. Coordinator duties (you, between agents)
- Relay cross-tile findings immediately with the evidence (tile, px box, gid).
- When an object hides another and nobody can tell which object it is, cast rays from the tile camera through the painted
  pixel into the built .blend and name the first object hit. In the reference this found the true owner of several
  long-standing blockers (an awning attached to a neighbour's building, a back roof from the tile next door).
- When two tiles' corrections conflict in their 200 px overlap, prefer the tile with stronger painted evidence
  (figures or goods standing on the object beats an empty strip).
- Fix generators for problems that repeat across tiles instead of patching each tile.
- After all correctors finish: validate every overrides JSON, rebuild layout, rebuild scene, render, compose, regenerate
  contexts, then run all 41 verifiers again.

### 5e. Rounds
Repeat 5a-5d. After each round: archive verdicts, compute mean score and ok / wrong / missing / ignore totals, compare with
the previous round, list which tiles changed, update PLAN.md, publish the review page (all rounds side by side, score history
per tile).

Stopping rule: stop the loop when two consecutive rounds raise the mean by less than 0.1, and switch to Phase 6.

## Phase 6. Performance and delivery
- Instanced or merged static crowds, LOD meshes, per-zone loading, mesh compression (Draco or meshopt), a mobile profile.
- Publish the viewer with the catalogue, plan and verification pages alongside, so every object cites its source.

## Known pitfalls from the reference run (check for each one early)

1. Horizontal moves converted at the object's own row scale come out about 30% short near the bottom of a tile; use one
   consistent scale for move_px.
2. Upper-floor objects use a fixed lift (about 3.1 m in the reference) and lose it when moved; recompute the lift after a move.
3. Roof pitch should honour the measured ridge height, but stale ridge heights from early specs can flatten many roofs at once;
   validate before switching it on globally.
4. Mounds and banks built as faceted ellipsoids read as pale boulders. Build low, smooth-shaded domes with a sunk skirt, or
   raise the terrain heightfield instead.
5. A "count" field on repeated props (stones, jars) laid out in one straight row can run 7 m across a neighbour's building.
   Lay repeated props out as a heap.
6. Signs and boards can be built twice: once inside a building spec and once as a separate prop. Keep one.
7. Boats turned into the depth axis render foreshortened and too short; check heading against the painted length.
8. Separate props on an animal's back (sacks, loads) float when the animal moves. Parent loads to their animal.
9. Willow and bare-tree crowns came out as wires and columns for many rounds; budget enough vertices for dense twig crowns.
10. The Rainbow Bridge arch needs its painted rise. Shifting the bridge does not fix a too-flat arch.
11. Water polygons near the moat can cover painted road; check the shoreline against the scan.
12. Verifiers can blame the wrong object for a blocker. Before acting on "X hides Y", confirm the owner (raycast).
13. Duplicate objects across the 200 px overlap: removing one tile's copy can look like a regression to the other tile's
    verifier. Record the decision in both tiles' notes so the next verifier marks it ignore, not missing.

05Token-count script

For Claude Code. Save as count_tokens.py, run python3 count_tokens.py ~/.claude/projects/<folder>. Same method as the numbers above.

count_tokens.py
import json, glob, os, sys
from collections import defaultdict
from datetime import datetime
# usage: python3 count_tokens.py ~/.claude/projects/<your-project-folder>
root = os.path.expanduser(sys.argv[1])
seen=set(); M=defaultdict(lambda:[0]*5); D=defaultdict(lambda:[0]*4); ts=[]
for f in glob.glob(os.path.join(root,'**/*.jsonl'), recursive=True):
    for l in open(f, errors='ignore'):
        try: d=json.loads(l)
        except: continue
        t=d.get('timestamp')
        if t: ts.append(datetime.fromisoformat(t.replace('Z','+00:00')))
        m=d.get('message')
        if d.get('type')=='assistant' and isinstance(m,dict) and m.get('usage'):
            k=(m.get('id'), d.get('requestId'))
            if k in seen: continue
            seen.add(k); u=m['usage']
            v=[u.get('output_tokens',0), u.get('input_tokens',0),
               u.get('cache_creation_input_tokens',0), u.get('cache_read_input_tokens',0)]
            r=M[m.get('model')]; r[0]+=1
            for i in range(4): r[i+1]+=v[i]; D[t[:10]][i]+=v[i]
ts.sort()
active=sum((b-a).total_seconds() for a,b in zip(ts,ts[1:]) if (b-a).total_seconds()<1800)
print('model  responses  output  input_uncached  cache_write  cache_read')
for k,r in M.items(): print(k, *r)
print('day  output  input_uncached  cache_write  cache_read')
for k in sorted(D): print(k, *D[k])
print('active hours (gaps < 30 min):', round(active/3600,2))
print('first/last:', ts[0], ts[-1])
